## 1. О проекте

Учебный Food Delivery (по образцу Додо Пицца): **шаурма и пицца** + сеты со скидкой, напитки, десерты. Каждый модуль демонстрирует фичу Next.js 16. Full-stack без отдельного бэкенда.

Зафиксировано:

- UI на русском
- Светлая и тёмная темы — равнозначные
- Доступность WCAG 2.1 AA / EN 301 549 (EU Accessibility Act)
- Учебный, но с прод-практиками: **готов к деплою в Docker в любой момент**; **CI: GitHub Actions — push в master гоняет юниты (vitest) + e2e (@playwright/test, chromium) с этапа 12** (гриллинг Q9 2026-11-18 — правка прежней конвенции «без CI»)
- Production-ready-похожий на бесплатных заглушках (гриллинг 2026-11-15): SMS — фейк-код `1111` + консоль, email — SMTP → Mailpit, оплата — мок-провайдер с webhook-контрактом; настоящий провайдер = новый файл + env, без переделки логики
- Пакетный менеджер — **pnpm 11**; npm/yarn не используем

## 2. Стек

Next.js 16.4.6 (App Router, Turbopack, Cache Components, Partial Prefetching, React Compiler) · React 19.3 · TypeScript strict · Tailwind v4 + shadcn/ui (radix, preset nova) · **PostgreSQL 17 в docker-compose + Drizzle ORM (pg-core, драйвер postgres-js, миграции drizzle-kit)** · better-auth (phone-number plugin: регистрация/вход по телефону с SMS-OTP, email-верификация кодом из письма; роли admin/manager/customer) · **MinIO (S3-совместимое хранилище; клиент @aws-sdk/client-s3) + sharp (обработка фото)** · **WebSockets — `ws`: отдельный шлюз `ws-gateway` (workspace-пакет, второй процесс в docker-compose) + Postgres LISTEN/NOTIFY (фанаут сообщений чата)** · next-themes · nodemailer (SMTP → Mailpit) · pino (структурные логи) · zod (валидация env) · **react-hook-form + zod** (формы: правила в `lib/schemas/`, тип формы = `z.infer`, клиент — zodResolver, серверная часть парсит ту же схему в safeParse — CheckoutForm переписана 2026-11-15, админ-формы этапа 5 — так же) · **тесты (этап 12): vitest — юниты чистых функций `lib/` (`*.test.ts` ко-локация) + `@playwright/test` — e2e против `next build`+`next start` (`pnpm test:unit` / `pnpm test:e2e`; сценарии P1 смоук → P2 ядро → P3 сложные, chromium, workers:1, БД `food_delivery_e2e` в том же postgres)** · **Storybook 10 + `@storybook/nextjs-vite` (этап 13): 50 стори × 13 компонентов ко-локацией, theme-toolbar light/dark, addon-a11y; серверные модули замоканы Vite-алиасами, App Router-контексты — провайдер в preview; axe-аудит `scripts/storybook-a11y.mjs`** · пакетный менеджер **pnpm 11** (pnpm-workspace.yaml с `allowBuilds`; npm/yarn не используем).

Решения гриллинга 2026-11-15 (полная картина — §6, §8, §11): **без отдельного бэкенда** — монолит Next.js: чтения RSC напрямую из БД, записи Server Actions, Route Handlers ровно 6 (+ payment-webhook, + health; этап 9 добавил седьмой — confirm для loopback-подписи); **Postgres вместо SQLite** с этапа 0; **серверная корзина вместо Zustand**; **максимальное кеширование** (§5.3, §6, §11); **production-ready-заглушки** (вторая сессия гриллинга 2026-11-15): auth по телефону + верифицируемый email, 8 статусов, PaymentProvider + payments + webhook, аутбокс `notifications` + SMS «заказ готов», автоджоба статусов, ops-харднинг — этапы 9–11 в §6, грабли §5.15–18, детали §11.

## 5. Технические грабли (обязательны к соблюдению)

1. **Доки Next.js — в пакете**: `node_modules/next/dist/docs/`.
2. **next.config.ts**: `cacheComponents: true`, `partialPrefetching: true`, `reactCompiler: true` (+ dev-dep `babel-plugin-react-compiler`), `output: 'standalone'` (Docker).
3. **Cache Components**: кешируемые async-функции: `'use cache'` + `cacheLife()` + `cacheTag()`; теги: меню → `'menu'`, акции → `'promos'`, заказы → `'orders'`; профили `cacheLife` сверены с доками v16 (`hours` = stale 5м / revalidate 1ч / expire 1д). После мутаций: **`updateTag(tag)` в Server Actions** (read-your-own-writes; одиночный `revalidateTag(tag)` в v16 deprecated, в Route Handlers — `revalidateTag(tag, "max")`). Доступ к `cookies()`/`searchParams`/`new Date()` — только в некешируемых скоупах, оборачивать в `<Suspense>` (searchParams передавать вниз PROMISE'ом); исключение — `new Date()` ВНУТРИ `'use cache'` (результат кешируется, пример — год в футере); для **Route Handlers** `connection()` не нужен — чтение `request` уже делает роут динамическим (v15+ GET динамические по умолчанию). Для `new Date()`/`Math.random()` вне кеша Suspense мало — нужен `await connection()` ПЕРЕД вызовом; кешируемые запросы исполняются на пререндере сборки → `connection()` ДО них, иначе docker build требует живую БД. `connection()` импортируется из **`next/server`**, не из `next/headers` (в 16.4.6 его там нет — «connection is not a function»). **`getSession` (lib/session.ts) обязан звать `await connection()` ДО `auth.api.getSession`**: у залогиненного юзера cookieCache-hit внутри better-auth читает `Date.now()` (сравнение expiry) — без гейта dev-пререндер soft-навигации падает «Blocking Route» (проявилось на этапе 3: до него никто не был залогинен и ветка не исполнялась; build не ловит — на сборке сессий нет). **Аргументы `'use cache'`-функции — часть кеш-ключа**: время внутрь не передавать. **Акции**: кешируются данные (`isActive = true`), окно `startsAt/endsAt` — фильтр на чтении вне кеша (`isPromoInWindow`, `lib/promo.ts`); **страница `/promo` целиком не кешируется** — кешируемая оболочка + список в Suspense, иначе отрендеренный список заморозится.

23. **WebSockets (решение 2026-11-15; уточнено гриллингом этапа 6, 2026-11-17 — вариант C)**: в Route Handlers WS не работают (доки Next, `backend-for-frontend.md` — соединение закрывается по таймауту); кастомный сервер отпадает — ломает `output: 'standalone'` (п. 2) и Docker-дисциплину (п. 13). Решение — **отдельный WS-шлюз** `ws-gateway/` (workspace-пакет, Node + `ws`, порт 3001): шлюз — транспорт + релей записей (комнаты, LISTEN, ping/pong), персист и валидация остаются в Next; auth при upgrade — cookies пересылаются в `/api/auth/get-session` (куки не изолируются по порту — localhost:3000 и :3001 делят их) либо кука `chat_token` гостя; **записи клиента И оператора — единым WS-релеем** (Q1 этапа 6): `{type:"send"}` → шлюз → служебный `POST /api/chat/internal` (`x-internal-secret`; discriminated union send|read|join) → живая перевалидация identity по БД → INSERT + NOTIFY в транзакции — секрет в браузере не живёт, Server Actions для чата отклонены (два пути записи = ручная стыковка optimistic/broadcast и гонка двух транспортов). Шлюз валидирует subscribe через internal один раз на соединение (кеш в памяти); фанаут — Postgres LISTEN/NOTIFY (канал `chat`, payload < 8 КБ — телефон для таба кладёт Next в payload, шлюз без БД-чтений); URL шлюза клиенту — `NEXT_PUBLIC_WS_URL` (§5.32-г — печётся на build); dev — шлюз на хосте `pnpm dev:gateway`, контейнер только в prod-compose.

Фикс трёхчастный: (а) `serverExternalPackages` += пакеты, нужные вне бандла; (б) file-tracing копирует `.pnpm`-store, но root-симлинк может не создать (drizzle-orm — нет, postgres — есть) → ручной `RUN cd node_modules && ln -s .pnpm/имя@*/node_modules/пакет пакет` — **glob расширяется от CWD, только из `cd node_modules`**; (в) проверка резолва на сборке: `node --input-type=module -e "await import('…')"` прямо в RUN — упадёт образ, а не контейнер в restart-loop. Смежное: **instrumentation.ts регистрируется и для Edge-бандла** — гвард `NEXT_RUNTIME !== 'nodejs'` в register() ОБЯЗАТЕЛЕН, и никаких СТАТИЧЕСКИХ импортов node-only модулей в instrumentation.ts (статический `import { IS_BUILD } from '@/lib/env'` тянул env/logger в Edge → «Ecmascript file had an error»; только литералы NEXT_PHASE/NEXT_RUNTIME внутри, node-код — через dynamic import в Node-ветке).
39. **Next 16 держит предыдущие деревья маршрутов в DOM скрытыми (Activity-ресторация) — правило e2e-локаторов** (тикет 02 этапа 12): после клиентской навигации `/` → `/cart` → `/checkout` → `/orders/[id]` в DOM живут ВСЕ пройденные деревья (display:none) — `getByText` матчит скрытые деревья (strict-violation на 3 элемента, а с `exact: true` — «hidden» на видимой странице); **`getByRole` скрытые деревья фильтрует сам** (ARIA-семантика исключает display:none). Правило: текстовые ассерты — только role-локаторы (`getByRole('listitem').filter({ hasText: … })`) или скоуп к видимой зоне; CSS-локаторы (`page.locator('li')`) скрытые деревья тоже видят.

## 8. Функциональная спецификация (кратко)

- **Happy path клиента**: главная `/` — **меню на ней** (секции: «Акции недели» в Suspense; sticky-навигация по категориям — якорный скролл + scrollspy, поиск `?q` через searchParams; «Популярное» — §9) → модалка товара (intercepting, открывается по ссылке `/product/[id]` с главной) → корзина (серверная: `carts`/`cart_items`; гостю — httpOnly cookie `cart_id`, при логине слияние) → акции из блока корзины (публичные, кнопкой) или скрытый промокод (поле ввода) → чекаут (контакты + способ оплаты) → заказ (uuid) → трекинг `создан → готовится → готов → (в доставке → доставлен | выдан)` (+ `отменён клиентом` / `отменён заведением — не принят`), при `готов` — SMS через аутбокс, polling 25 с (ETag → 304). Auth: вход по телефону (SMS-OTP фейк `1111`), регистрация — email + phone, email верифицируется случайным кодом из письма (Mailpit). Закрытые страницы: `/admin/*` — admin+manager; `/orders`, `/orders/[id]` (+ pay) — владелец по сессии, гостю — uuid-ссылка. Поддержка: плавающий чат-виджет на любой странице (этап 6, §5.22) — тред с операторами из `/admin/chats` (табы: телефон клиента или «unknown» для гостя)
- **API**: Route Handlers — ровно 8: `GET /api/orders/[id]`, `GET /api/promotions` (только публичные — скрытые промокоды через API не отдаются), `POST /api/chat/init` + служебный `POST /api/chat/internal` для WS-шлюза (этап 6), `/api/auth/[...all]` (send-phone-otp, sign-in phone, sign-up phone+email, verify-email, sign-out, get-session), `POST /api/payments/mock/webhook` (этап 9, HMAC) + `POST /api/payments/mock/confirm` («бэкенд провайдера» — серверная подпись + loopback на webhook, этап 9), `GET /api/health` (этап 11: SELECT 1 + headBucket, таймауты 2 с, 200|503 + checks, no-store).
