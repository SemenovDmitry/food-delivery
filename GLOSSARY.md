# Food Delivery

Учебный проект доставки еды (шаурма и пицца, по образцу Додо Пицца) на Next.js 16. Словарь — из AGENTS.md; источником правды по плану и статусу остаётся AGENTS.md, здесь — только язык домена.

## Language

**Заказ**:
Сущность в `orders` с неугадываемым uuid; трекинг по uuid доступен гостю без входа.
_Избегать_: покупка, транзакция

**Статус заказа**:
Фиксированное множество из 9 значений (`ORDER_STATUSES`): цепочка `создан → готовится → готов`, ветка по fulfillment — `в доставке → доставлен` (delivery) | `выдан` (pickup); терминальные отмены — `отменён клиентом`, `отменён заведением (не принят)`, `отменён автоматически` (`cancelled_by_timeout` — истекло окно оплаты, пишет только система). Подписи — `STATUS_LABELS`.

**Одиночный товар**:
Товар `type = single`; цена — одна, в копейках.
_Избегать_: «простой товар»

**Сет**:
Товар `type = set` со скидкой; состав — строки в `set_items`; выгода показывается зачёркнутой старой ценой (`setOldPrice` — сумма цен компонентов).
_Избегать_: комбо, комплексный обед

**Копейка**:
Единица хранения всех денежных сумм: int в копейках. Вывод в рублях — только через `formatPrice()`.
_Избегать_: float, хранение рублей в БД

**Снапшот цены**:
Цена и название товара, зафиксированные в `order_items` из БД на момент создания заказа; ценам из клиента не доверяем.
_Избегать_: «текущая цена» в контексте заказа

**Акция**:
Сущность в `promotions`: `discountType` percent|fixed, скоуп — `categoryId` (null = весь заказ) + `minTotal`, окно `startsAt/endsAt`, `isActive`, `isPublic`. Читается кешируемым `getActivePromotions()` с тегом `promos`; скидку считает `calcDiscount` — единая для корзины, чекаута и apply.
_Избегать_: скидка (это тип расчёта, не сущность)

**Промокод**:
`code` акции (nullable). Безкодовые акции — только реклама в ленте, к корзине не применяются. Ввод кода и ревалидация — на сервере (`applyPromoCode`, `createOrder`).
_Избегать_: купон

**Публичная акция**:
Акция `isPublic = true`: видна в ленте «Акции недели», на `/promo`, отдаётся `GET /api/promotions` и показывается в блоке акций корзины (кнопка «Применить»).
_Избегать_: «обычная акция»

**Скрытый промокод**:
Акция `isPublic = false`: нигде не показывается — ни лента, ни `/promo`, ни блок корзины, ни API. Единственный путь применения — ввод кода в поле на /cart. Канал распространения — вне приложения (рассылка, реклама); инпут существует именно для них.
_Избегать_: секретная акция, «тайная скидка»

**Fulfillment**:
Способ исполнения заказа: `delivery` | `pickup`.
_Избегать_: «тип доставки» для pickup

**Кеш-тег**:
Строка тега Cache Components из фиксированного набора: `menu`, `promos`, `orders`; после мутаций — `revalidateTag()`.
_Избегать_: произвольные теги вне набора

**Этап**:
Блок плана работ из раздела 6 AGENTS.md (0–11); завершение = чекбоксы `[x]` + обновление раздела 3 + коммит.
_Избегать_: «фаза», «спринт»

**Аутбокс**:
Очередь исходящих уведомлений в `notifications`: строка пишется в той же транзакции, что и событие; флушер (интервал 30 с) отправляет pending через провайдера и помечает sent|failed. OTP и письма-коды идут мимо аутбокса — напрямую.
_Избегать_: отправка SMS прямо в экшене

**Флушер**:
Отправитель аутбокса: `setInterval`-синглтон 30 с, стартует из `instrumentation.ts` (раз на процесс сервера). Берёт pending из `notifications` (батч 20 по createdAt), шлёт провайдером канала, помечает `sent|failed` (+error). `failed` — терминален, ретраев нет. Провайдеры — seam: SMS — консоль-заглушка, email — `sendEmail` (Mailpit; без `SMTP_HOST` — консоль).
_Избегать_: очередь в памяти, отправка в request-потоке

**OTP-код**:
Код подтверждения: телефон — SMS, в демо всегда `DEMO_SMS_OTP_CODE` (`1111`); email — случайный код письмом через Mailpit. Хранится/проверяется better-auth, UI показывает «отправлено».
_Избегать_: пароль

**Мок-провайдер**:
`MockProvider` за интерфейсом `PaymentProvider`: `initiate` возвращает externalId и redirectUrl на локальную страницу «сайт провайдера» (`(provider)/orders/[id]/pay` — без шапки магазина, шаг выбора банка + заглушка банка). Подтверждение щёлкается на заглушке, подпись HMAC ставит сервер: confirm-эндпоинт делает loopback HTTP POST на `POST /api/payments/mock/webhook` — секрет никогда не в браузере. Замена на реального = новый файл + `PAYMENT_PROVIDER`.
_Избегать_: «фейковая оплата» — это настоящий контракт с заглушкой

**Онлайн-оплата**:
Способ оплаты в чекауте (`orders.paymentMethod`: `online | on_receipt`). Заказ создаётся сразу, но кухня его не стартует до оплаты; банк-провайдер выбирается на следующем шаге, не в чекауте.
_Избегать_: «предоплата» (есть «при получении»), «оплата картой» (инструмент выбирается позже)

**Провайдер оплаты**:
Банк-заглушка в `payment_methods` (`sber`, `unionpay`), включается/выключается тумблерами `/admin/payments`; код пишется в `payments.provider`. Отключение не влияет на созданные заказы; «Онлайн-оплата» доступна, пока активен хотя бы один.
_Избегать_: PaymentProvider (это шов реализации `lib/payments/`), «способ оплаты»

**Окно оплаты**:
5 минут (`PAYMENT_WINDOW_MINUTES`) с момента создания на оплату онлайн-заказа; отсчёт — на странице оплаты. Просрочка: система ставит `cancelled_by_timeout` (ленивые TTL-гарды + свип в тике автоджобы, который работает всегда).
_Избегать_: «таймер заказа», автосписание

**Mailpit**:
Локальный контейнер в dev-компоузе (SMTP :1025, UI :8025), принимает письма по-настоящему по SMTP. Без `SMTP_HOST` email-транспорт падает в консоль-заглушку.
_Избегать_: «настоящая почта», платный почтовый хостинг

**Автоджоба**:
`lib/jobs/auto-status.ts`, тик раз в `DEMO_AUTO_STATUS_INTERVAL` (мс, кламп ≥ 5 с), стартует из `instrumentation.ts`. Внутри тика: **свип — всегда** (dev и prod), продвижение статусов — под `DEMO_AUTO_STATUS=true` (dev on / prod off). Продвижение — по-заказный elapsed (`updatedAt` старше интервала → один шаг по `nextStatuses`); неоплаченные онлайн не продвигаются (их берёт свип). Рол `DEMO_AUTO_CANCEL_RATE` (дефолт 0.1) — одиночный, в точке `created→preparing`, только on_receipt; оплаченные не отменяются никогда.
_Избегать_: автооплата, автоподтверждение оплаты, локстеп-продвижение

**Свип**:
Активная часть тика автоджобы, работает всегда: находит просроченные онлайн-заказы (предикат TTL-гарда webhook-core: online + pending + истекло окно) и по-заказными транзакциями ставит `cancelled_by_timeout` + payment `cancelled` + событие. Системный писатель `cancelled_by_timeout` для случая «клиент ушёл и не вернулся»; ленивые гарды остаются страховкой.
_Избегать_: cron, «фоновой процесс» (в проекте один — тик автоджобы)

**Env-схема**:
`lib/env.ts` — единственный серверный источник env (zod). На build (`NEXT_PHASE=phase-production-build`) — lenient (фолбэки, без throw: секретов на сборке нет); при рантайме — strict: ошибка → читаемый список → `exit(1)` на старте контейнера. `NEXT_PUBLIC_*` вне схемы — клиент читает `process.env` напрямую (инлайн на build).
_Избегать_: прямой `process.env` в серверном коде, молчаливые клампы env-значений

**Sink (DB-sink)**:
Дополнительный pino-стрим: записи `level ≥ 40` (warn/error/fatal) fire-and-forget'ом падают в `error_events` (`context` несёт requestId/component). Сбой вставки молчит — цикла «DB лежит» нет; stdout пишется всегда. Задел под Sentry (§9).
_Избегать_: ручные INSERT в error_events из catch-блоков

**Request-ID**:
`x-request-id` (uuid) на каждый HTTP-запрос: ставится proxy'ем в request-заголовки и в ответ `X-Request-Id`; читается `getRequestId()` только в некешируемых скоупах (Route Handlers, Actions, error-границы). Джобы без requestId — у них `component`. Клиент может процитировать id в чате поддержки.
_Избегать_: request-id в `'use cache'`-функциях

**Throwaway-проект**:
Временный docker compose-проект (`docker compose -p stage11check`) с собственными volume'ами — fresh-migrate и env-тесты без риска общим `food-postgres-data`/`food-minio-data` (dev и prod делят volume'ы — §5.26). Порты: поднимается до основного prod-стека или после его остановки.
_Избегать_: снос общих volume'ов ради теста

**Fresh-migrate**:
Прогон миграций entrypoint'ом (`scripts/migrate.mjs` → server.js) на пустом volume: контейнер сам создаёт схему при старте; идемпотентно по `__drizzle_migrations` — рестарт проходит повторно молча. Dev-поток не меняется (`pnpm db:migrate` вручную).
_Избегать_: `db:push`, миграции руками в контейнере

**Тред поддержки**:
Один постоянный диалог в `chat_threads` на идентичность (Q2): у клиента — по `user_id`, у гостя — по `guest_token` из куки `chat_token`; тредов-на-заказ нет. Гостевой тред усыновляется при логине (`user_id` проставляется), только если у юзера ещё нет своего; потоки сообщений не мержатся.
_Избегать_: «диалог заказа», «сессия чата»

**Сообщение чата**:
Строка в `chat_messages`: `direction` customer|operator, текст 1..2000 после trim (валидация `lib/schemas/chat.ts`), `sender_id` — автор (гость-клиент даёт null). Порядок отображения = id (bigserial).
_Избегать_: «пост», «месседж»

**Направление сообщения**:
`CHAT_DIRECTIONS`: `customer` — пишет клиент, `operator` — отвечает персонал. Определяет бейджи непрочитанных: customer-сообщения считаются для оператора, operator — для клиента.
_Избегать_: inbox/outbox

**Операторская**:
`/admin/chats` — рабочее место персонала (admin+manager): табы тредов по последнему сообщению, телефон клиента или «unknown» для гостя, непрочитанные на табах, ответ из таба. Клейма/назначения нет — все операторы видят все треды (Q6).
_Избегать_: «чат-панель», «саппорт-страница»

**WS-комната**:
Группировка подписок шлюза в памяти: комната на тред (клиент) + общая комната `operators`. Сообщения фанаутятся из NOTIFY канала `chat`; шлюз БД не читает — телефон для таба кладёт Next в payload при вставке.
_Избегать_: «канал» (канал — это NOTIFY-канал в Postgres)
