Сценарий:

1. **Happy path онлайн (гость)**: сет+шаурма → промо → чекаут «Онлайн-оплата» → заказ → pay-страница (без шапки магазина) → Сбер → «Оплатить» → трекинг: «Оплачено» ≤25 c без перезагрузки (`timeOrigin` неизменен). БД: `orders.paymentMethod='online'`, `paymentStatus='paid'`, `payments`: одна строка, `status='paid'`, `provider='sber'`, amount = subtotal − скидка + доставка.
2. **«Отмена» банка (Q19)**: новый заказ → Сбер → «Отмена» → payment `failed` → возврат на шаг 1 → повтор → `paid` (та же строка payments, новый externalId).
3. **Грани pay-страницы (Q7)**: paid-заказ → redirect; on_receipt-заказ → redirect; не-uuid → 404; чужой заказ по uuid без payment → redirect.
4. **Кухня (Q18)**: неоплаченный онлайн у админа — select disabled «Ожидает оплаты»; curl action → «Заказ ожидает оплаты»; оплатить → `preparing` проходит; трекинг показывает смену.
5. **Timeout (Q17)**: SQL `UPDATE orders SET created_at = now() - interval '10 minutes'` → «Оплатить» → pay → «Оплатить» → отказ (409) → заказ `cancelled_by_timeout` + строка в `order_status_events`; баннер «Время оплаты истекло»; повторная оплата невозможна, «Повторить заказ» работает.
6. **on_receipt → paid (Q21)**: заказ «при получении» → админ доводит до `delivered` → `paymentStatus='paid'` в БД, чип «Оплачено»; `picked_up` — аналогично.
7. **Тумблеры (Q14/Q20)**: `/admin/payments` выключить обоих → чекаут без «Онлайн-оплаты» (мягко); создать заказ «при получении» — ок; включить обратно; заказ, созданный с выключенным потом провайдером, платится (Q12 — старые заказы не ломаются).
8. **curl-негативы webhook**: кривая подпись → 400; чужой/несуществующий paymentId → 404; **replay** оплаченного → 200 (БД не изменилась); webhook на отменённый заказ → 409; на просроченный → 409 (или через confirm — тот же исход).
9. **Регрессия**: `cancelOrder` клиента неоплаченного онлайн-заказа (до оплаты) работает (`cancelled_by_customer`); прежние on_receipt-заказы отображаются как раньше; чат/поллинг не задеты.
