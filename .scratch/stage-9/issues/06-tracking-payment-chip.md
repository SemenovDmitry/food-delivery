# 06: Трекинг — платёжный чип, CTA «Оплатить», баннер timeout

**What to build:** `/orders/[id]` (Q9): рядом со `StatusBadge` — платёжный чип **всегда**: `online + pending` → «Ожидает оплаты» (accent-токен) + кнопка «Оплатить» → `/orders/<id>/pay`; `paid` → «Оплачено» (success-токен); `on_receipt` → «При получении» (нейтральный). Чип виден владельцу и держателю uuid-ссылки — статус оплаты не чувствителен (семантика Q11a: uuid = статус, сессия = чувствительное); кнопка CTA — тоже (платить может держатель ссылки: гость платит свой заказ). Query страницы расширить на `paymentMethod` (+ payment-строка не нужна — состояние живёт на order). **Баннер отмены** (этап 4: destructive-баннер вместо таймлайна) — текст ветвится по статусу: `cancelled_by_timeout` → «Время оплаты истекло, заказ отменён» (новый, Q17); `cancelled_by_customer` / `cancelled_by_vendor` — текущие тексты уточнить («Заказ отменён заведением — не принят»). RepeatOrderButton остаётся для всех терминальных (после timeout «повтор заказа» — главный путь, Q17). Живое обновление чипа — существующий `OrderTracker`-поллинг 25 c (`paymentStatus` уже в DTO `GET /api/orders/[id]`), после оплаты чип меняется без перезагрузки. A11y §7: чип не только цветом (текст), кнопка — явный label.
