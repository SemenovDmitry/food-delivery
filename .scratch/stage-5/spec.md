# Спека: Этап 5 — Админка + картинки

Источник правды: AGENTS.md (§6 этап 5, §5.9 proxy, §5.29 updateTag, §7 a11y). Гриллинг этапа 5 (2026-11-16, раунды 1–3, Q1–Q27) **переопределил план**: смена роли в UI удалена (Q12) → вместо неё **бан и архивирование** пользователей (Q14/Q24); добавлены CRUD категорий (Q17) и **позиции с Drag-and-Drop** для категорий и товаров (Q25/Q26); **пагинация + perPage** на всех списках кроме категорий (Q19/Q27); удаление пользователей — **софт** (`deleted_at`, Q15-эволюция); удаления товаров и акций — наоборот хард (Q16/Q9); картинки — **ключ в БД, URL из env** (Q7) с кеш-стратегией immutable (Q8); **без promoName-снапшота** (Q23, осознанно); `src/proxy.ts` создать (факт: не существует, §5.9 описывал задел); live-обновлений в списках нет (Q22).

## Problem Statement

Зона `/admin` пуста: ни одного роута нет, `getAdminSession` не имеет callers, `src/proxy.ts` не существует. Статусы заказов меняются только прямым SQL; каталог и акции живут только из сидера; `imageUrl` у всех товаров null — витрина на emoji; настройки доставки правятся руками в таблице `settings`. Персонал неуправляем: забанить/удалить пользователя нельзя, вход заблокированного ничем не режется.

## Solution

Админка tracer-bullet'ом: каркас (layout, нав по роли, proxy, живые гарды) → `/admin/orders` + `updateOrderStatus` (карта переходов) → CRUD товаров и категорий (позиции + DnD) → картинки (S3 + sharp, ключ в БД) → CRUD акций → юзеры (бан/архив) + настройки доставки. Все формы — RHF+zod в `lib/schemas/` (паттерн CheckoutForm); все мутации — Server Actions с `updateTag`; списки — RSC с searchParams-фильтрами и пагинацией.

## User Stories

1. Как manager, я хочу видеть все заказы с фильтром по статусу и менять статус select'ом прямо в строке — а покупатель увидит это на трекинге ≤25 с.
2. Как admin, я хочу создать сет с составом, скрыть товар из каталога или удалить его, загрузить фото — и видеть всё это на витрине.
3. Как admin, я хочу менять порядок категорий и товаров перетаскиванием (и с клавиатуры), чтобы управлять витриной без SQL.
4. Как admin, я хочу создавать/править/удалять акции со всеми условиями (скоуп, minTotal, окно, публичность).
5. Как admin, я хочу банить и архивировать пользователей — забаненный теряет доступ при следующем же запросе, архивированный исчезает из списка, но его заказы остаются атрибутированными.
6. Как admin, я хочу менять цену доставки и порог бесплатной доставки через форму, а не SQL.

## Implementation Decisions (гриллинг Q1–Q27, 2026-11-16)

- **Q1 — разрезка**: tracer-bullet: ① каркас+миграции → ② заказы+статусы → ③ товары+категории (без картинок) → ④ картинки → ⑤ акции → ⑥ юзеры+настройки. Риск MinIO/sharp изолирован в шаге ④.
- **Q2/Q21 — каркас**: `/admin` → redirect `/admin/orders` (без дашборда). `src/proxy.ts` создаём — matcher `/admin/:path*`, fast-fail по cookieCache-сессии → redirect `/login` (синтаксис по докам v16 в node_modules, §5.1). Живая проверка остаётся в layout/actions — proxy это UX-слой быстрого отсева. Manager: только «Заказы» в наве; admin-only страницы (`products|categories|promotions|users|settings`) при заходе manager'а — тихий `redirect('/admin/orders')`, без 403-страницы.
- **Q14 — живая проверка ролей/бана**: cookieCache (5 мин) не доверяем в гардах: после `getSession` свежий `SELECT role, banned_at, deleted_at FROM "user"` по `session.userId` (один PK-lookup). Несоответствие роли зоне / бан / архив → `signOut` (убивает сессию и cookie) → redirect `/login` с тостом. Это и есть «ошибка → очистить сессию», только проактивно при каждом guarded-запросе. better-auth admin-плагин отклонён: impersonation/banExpires/adminClient ради двух кнопок.
- **Q24 — бан и архив — независимые флаги**: `banned_at` = наказание (тост «Аккаунт заблокирован»), `deleted_at` = «Аккаунт удалён»; оба режутся одной live-проверкой и гардами входа (до `sendPhoneNumberOTP` — SMS не уходит). Список юзеров фильтрует `deleted_at IS NULL`; restore-UI нет (при нужде — SQL). `orders.userId` не трогается — история остаётся атрибутированной (это и стало причиной отказа от хард-делита, Q15).
- **Q3 — матрица переходов**: `nextStatuses(status, fulfillment)` в `lib/order-timeline.ts` — только вперёд по цепочке своего fulfillment, назад никогда; `cancelled_by_vendor` разрешён из `created|preparing|ready`. Select в строке показывает только легальные статусы. Сервер: `updateOrderStatus` — гард live-сессии, paid-гвард (оплаченные не отменяются никогда — refund вне скоупа, этап 9), транзакция с conditional `UPDATE ... WHERE id AND status = ожидаемый` (гонка, паттерн `cancelOrder`) + строка в `order_status_events` в той же транзакции (Q15a этапа 4) + `updateTag('orders')`. SMS «заказ готов» — НЕ здесь (этап 10, граница неразмываема). Manager и admin — оба могут.
- **Q12/Q18 — роли**: смены роли в UI НЕТ (чекбокс AGENTS «admin — смена роли» снят); сотрудники заводятся только сидером. Роль в `/admin/users` — display-only колонка.
- **Q16 — товары**: миграция `products.isActive`. Деактивация — скрывает из каталога (`getFullMenu` фильтр `isActive = true`), корзину не трогает (товар «снят с меню, но у тебя в корзине» — заказываем). Удаление хард: `cart_items` каскад (исчезает из корзин), `order_items` переживает (снапшот name/price + FK `set null` уже в схеме), гвард `set_items` (restrict) — «Товар входит в N сетов — сначала уберите оттуда» → toast.
- **Q17 — категории**: CRUD добавлен решением пользователя (сверх чекбоксов AGENTS). Слаг обязателен, латиница (`^[a-z0-9-]+$`) — он же якорь `#slug` sticky-навигации главной. Удаление с гвардом «в категории N товаров» (FK restrict) → toast.
- **Q25/Q26 — порядок и DnD**: `categories.position` + `products.position` (миграции; начальные значения пишет сидер по индексу). DnD — **@dnd-kit/core + sortable**: keyboard-сенсоры из коробки закрывают a11y-чеклист, touch работает; native `draggable` отклонён (без клавиатуры/тача, ломается на `scroll-behavior: smooth`, §5.25). Reorder — admin only; optimistic перестановка → action `reorder(ids)` в транзакции пишет `position = индекс массива` (нормализация дыр) → `updateTag('menu')`; ошибка → toast + откат. Товары сортируются внутри категории: на `/admin/products` чипы `?category=<id>` (паттерн `?status=` заказов), DnD внутри отфильтрованного списка; новый товар получает `max(position)+1` своей категории. `getFullMenu`: категории по `position` asc, товары внутри по `position` asc. В формах поля position нет — порядок только перетаскиванием.
- **Q19/Q27 — пагинация**: orders/products/users/promotions — `?page=` + `?perPage=` (10/25/50, default 25), SQL limit/offset + count, searchParams парсится zod'ом. Категории — БЕЗ пагинации: DnD между страницами не работает, список маленький (их `perPage=∞`). Пейджер «← 1 2 3 →»; shadcn `pagination` в ui/ нет — если реестр недоступен по сети (прецедент alert-dialog этапа 4), руками на Button.
- **Q7/Q8 — картинки**: deps `@aws-sdk/client-s3` + `sharp` (при предупреждении pnpm — флип `allowBuilds.sharp`, §5.4). В БД хранится **ключ** `products/<productId>/<sha256>.webp`, полный URL строит `imageUrlFor(key) = ${S3_ENDPOINT}/${S3_BUCKET}/${key}` при рендере — переживает переключение dev↔prod компоузов (общие volumes, §5.26: dev пишет `localhost:9000`, prod читает `minio:9000` — каждый стек строит URL из своего env). sharp: вход ≤5 МБ jpeg/png/webp → width 800 без апскейла → webp q80. `PutObject` с `CacheControl: public, max-age=31536000, immutable` — безопасен именно из-за хэш-ключа (новая картинка = новый URL); в next.config: `minimumCacheTTL` 30 дней + `remotePatterns` с hostname из `env.S3_ENDPOINT` (браузер MinIO не фетчит — только `/_next/image`). Замена фото: новый объект + удаление старого (без сирот); «Убрать фото» → `imageUrl = null` + deleteObject. Бакет public-read (анонимный GET для оптимизатора) создаётся идемпотентно в `db:seed`. Emoji-фолбэк (`products.emoji`, колонка есть) остаётся.
- **Q9/Q23 — акции**: CRUD полный: name, code (nullable, уникальность — серверная ошибка), discountType/Value, categoryId (null = весь заказ), minTotal, окно `startsAt/endsAt` (datetime-local, оба пустых = без окна, локальное время), isActive, isPublic. Удаление разрешено — FK `orders.promoId`/`carts.promoId` уже `set null`. **promoName-снапшот ОТКЛОНЁН** (Q23, решение пользователя): квитанция после удаления акции деградирует до безымянного «Скидка −300 ₽» (`discountAmount` выживает, имя резолвится джойном при чтении и теряется) — потеря атрибуции и статистики удалённых промо принята. `getAllPromotions()` без фильтров (задел комментария этапа 2); все мутации → `updateTag('promos')` (§5.29). Формы — отдельные страницы (паттерн товаров).
- **Q10/Q22 — UX заказов**: чипы `?status=` (все/активные/терминальные/конкретный), новые сверху, inline select статуса + `useOptimistic`; `paymentStatus` — read-only бейдж (его перевернёт webhook этапа 9). Live-обновлений нет: своё мгновенно, чужие правки видны при навигации/фильтре/пагинации. SSE отклонён: был бы третий push-механизм рядом с polling+ETag (этап 4) и WS-шлюзом (этап 6, чат).
- **Q13 — настройки доставки**: `/admin/settings` (admin only): два поля в рублях (step 0.01) → zod transform ×100 → копейки в `settings`; превью «Бесплатная доставка от X ₽»; `getDeliverySettings()` продолжают читать ключи — callers не меняются (шов этапа 1); после записи revalidatePath корзины/главной.
- **Формы**: все админ-формы — RHF+zod в `lib/schemas/` (`z.infer`-тип, zodResolver на клиенте, `safeParse` той же схемы на сервере — конвенция §2).

## Готово, когда

Гость и customer на `/admin` → редирект на `/login`; manager и admin входят и видят разную навигацию (manager на admin-only странице → redirect на заказы); смена статуса select'ом в `/admin/orders` видна на трекинге ≤25 с без перезагрузки (ETag 304/200 в Network); оплаченный не отменяется, назад перейти нельзя (негативы → toast); CRUD сета с составом работает; фото загружается и показывается на карточке витрины и в `/_next/image` с immutable-кешированием; деактивированный товар пропал из меню, но заказываем из корзины; удаление товара из состава сета — toast-гвард; DnD reorder категорий и товаров работает мышью и с клавиатуры, порядок виден на главной; акции создаются/правятся/удаляются, правка видна на витрине без холодного кеша (updateTag); забаненный при живой сессии теряет доступ на следующем guarded-запросе (signOut); поиск и пагинация на четырёх списках; смена доставки 199→299 видна в корзине; lint/tsc/build зелёные; docker build + prod compose (`up -d --build`, §5.28) + возврат dev (§5.26); скриншоты — `.scratch/stage-5/screenshots/`; AGENTS обновлён (чекбоксы + §3), коммит.

## Вне скоупа

SMS «заказ готов» и автоджоба (этап 10); платёжный UI и изменение `paymentStatus` вручную (этап 9); чат и WS (этап 6); дашборд; restore-UI архивированных; статистика использования промокодов; `promoName`-снапшот (Q23 отклонён); CRUD категорийных actions сверх UI; live-push в списках (SSE/WS); e2e-тесты; push в origin (по явной просьбе).
