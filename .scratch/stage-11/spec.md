Dev — transport `pino-pretty` (devDep) при `NODE_ENV !== 'production'`; prod — голый JSON в stdout; transport под Turbopack хрупок — фолбэк «JSON везде», если упадёт на смоуке. | Q7  | **Request-id через proxy**: matcher расширяется с `/admin/:path*` на все пути кроме статики (`_next/static`, `_next/image`, `favicon.ico`, `robots.txt`); `crypto.randomUUID()` → `x-request-id` в request-headers (вниз по цепочке) + `X-Request-Id` в response (клиент может процитировать в чате поддержки). Даунстрим — хелпер `getRequestId()`: `headers()` в try/catch (вне request-скоупа → null). Правило в духе §5.3: request-id читается ТОЛЬКО в некешируемых скоупах (Route Handlers, Actions, error-границы), в `'use cache'` не трогается. ## Архитектура

```
env      lib/env.ts — единственный серверный источник (образец ws-gateway/src/env.ts)
           NEXT_PHASE=phase-production-build → lenient (фолбэки; build не ломается)
           иначе strict: safeParse → читаемый список → exit(1) (fail-fast при старте —
           instrumentation.register импортирует env первым)
           tiers: prod-required | optional+defaults | NEXT_PUBLIC_* вне схемы (клиент читает сам)

логи     lib/logger.ts (pino): base {service, env}, LOG_LEVEL
           dev → pino-pretty transport (NODE_ENV !== 'production'), prod → JSON stdout
           sink: level ≥ 40 → fire-and-forget INSERT error_events (stack cap 8000,
                 context = {requestId, component, …}); сбой INSERT молчит
         proxy.ts: matcher = все пути кроме статики → x-request-id (request+response)
           getRequestId() — только в некешируемых скоупах (Route Handlers/Actions/error)

health   GET /api/health — SELECT 1 + headBucket(MinIO), AbortSignal.timeout(2000),
           200|503 + {status, checks}, no-store, warn при деградации (→ error_events)
         карта: app Dockerfile HEALTHCHECK (wget --spider, start-period 20s)
                minio — compose curl health/live (фолбэк TCP)
                ws-gateway — свой GET /health + compose wget
                postgres — pg_isready (уже есть)

entrypoint  scripts/migrate.mjs (retry ×3, идемпотентно) → CMD node migrate.mjs && exec server.js
              force-trace migrator через instrumentation; COPY drizzle + scripts в runner

backup   scripts/backup-db.sh — pg_dump plain+gzip на хосте; backups/ в .gitignore; README
```

- `env.ts` НЕ импортируется из клиентских файлов: `NEXT_PUBLIC_*` (`support-chat.tsx`, `chat-console.tsx`) остаются на прямом `process.env` — инлайнены бандлом на build (§5.32-г). `server-only`-маркер не ставим (seed импортирует s3.ts через tsx) — конвенция комментарием.
- Lenient-режим сохраняет существующие фолбэк-цепочки: `AUTH_SECRET ?? AUTH_SECRET_BUILD_FALLBACK` (better-auth валидирует секрет при инициализации модуля), `S3_ENDPOINT ?? S3_ENDPOINT_BUILD_FALLBACK` (next.config печётся на build, §5.3), dev-фолбэк `DATABASE_URL` (:5560, §5.20).
- `pnpm start`/tsx/seed на хосте: `NODE_ENV` не production → lenient → живут как живут; строгий режим включается только в контейнере (`NODE_ENV=production`, NEXT_PHASE не задан).
- Приёмка-фолбэк: если pino-pretty transport упадёт под Turbopack — фиксируем решение «JSON везде» в тикете 02 (код потребителей не меняется).

## Поток (канонический)

1. `docker compose -f docker-compose.prod.yml up -d --build` → контейнер app: strict env-парс → миграции (`__drizzle_migrations`) → `server.js`. Опечатка в env → exit(1) с читаемым zod-списком → контейнер crash-loop'ится, в `docker ps` виден нездоровым/мертвым — оператор диагностирует по логам `docker logs`.
2. Каждый HTTP-запрос получает `x-request-id` (в ответе тоже); ошибки/warn — в stdout JSON и в `error_events` с requestId; джобы пишут с `component`, без requestId.
3. Docker проверяет `/api/health` каждые 30 с; деградация (DB/MinIO) → 503 + warn → строка в `error_events`; контейнер помечается unhealthy.
4. Бэкап — вручную на хосте: `scripts/backup-db.sh` → `backups/*.sql.gz`; восстановление — по README.

## Данные и миграции

- **Миграций БД нет** (`error_events` этапа 0); «миграция» этапа = entrypoint в Docker.
- Env: `.env.example` += `LOG_LEVEL=info`, `BETTER_AUTH_URL=http://localhost:3000` (догоняем §5.32-а), комменты к tiers; локальный `.env` += `LOG_LEVEL`; prod-compose — ничего нового (`LOG_LEVEL` дефолт; ws-gateway `env.ts` += `LOG_LEVEL`).
- Deps: `pino` (prod), `pino-pretty` (devDep), `pino` в `ws-gateway/package.json`.

## Границы скоупа

- Без CSP/HSTS (после TLS/домена — §9; объяснение пользователю в гриллинге Q10).
- Без access-логов (pino-http) — флад stdout; логируем ошибки/warn/джобы/заглушки (Q7).
- Без cron-бэкапов (§9), MinIO не бэкапим (Q12).
- `seed.ts` и клиентский `error.tsx` остаются на console (Q9); sink активен и в dev, чистки error_events нет (Q13).
- `NEXT_PUBLIC_*` вне env-схемы (Q2); ws-gateway без `depends_on: app` (Q15).
