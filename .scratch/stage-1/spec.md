# Спека: Этап 1 — Корзина и чекаут (серверная корзина)

Источник правды: AGENTS.md (§6 этап 1, §5.10 корзина, §8 спецификация). Решения гриллинга 2026-11-15 (этап 1): скоуп-скидки (категория + minTotal в схеме), акции-заглушки в сидере (CRUD — этап 5), разделение потока /cart (редактирование) → /checkout (подтверждение), доставка 199 ₽ / бесплатно от 1000 ₽ (от суммы товаров до скидки), таблица `settings` сразу, fulfillment — только в заказе, квитанция вместо 404 после оформления. Термины — `GLOSSARY.md`.

## Problem Statement

Бэкенд корзины и заказа уже написан на этапе 0 (`addToCart`/`setQty`/`removeFromCart`, `createOrder`, `applyPromoCode`, `getOrCreateCart` с httpOnly-cookie `cart_id`), но UI нет: после добавления в корзину пользователь не может её посмотреть, применить промокод или оформить заказ. Скидка считается от всей корзины, хотя акции в сидере обещают «на шаурму»/«на пиццу» — враньё пользователю. Условий акции (минимальная сумма, скоуп) в схеме нет; стоимость доставки не существует; после «Оформить» пользователь падает в 404 (маршрут `/orders/[id]` появится только в этапе 4). Нужны страницы корзины и чекаута, модель скидок с условиями, доставка с порогом бесплатности и страница-квитанция.

## Solution

Двухстраничный поток: `/cart` — редактирование (степперы, удаление, промо-блок: доступные акции сверху с «Применить»/disabled+причина, активная ниже с ✕, поле кода с предзаполнением `?promo=`, Tabs доставки/самовывоза, полные тоталы с подсказкой до бесплатной доставки) → `/checkout` — подтверждение (товары read-only, контакты, адрес, комментарий, финальные тоталы, «Оформить заказ»). После оформления — страница-квитанция `/orders/[id]` (этап 4 надстроит трекинг). Схема: `promotions.categoryId` (null = весь заказ) + `promotions.minTotal`, `orders.deliveryFee`, таблица `settings` (key/value) для стоимости доставки и порога. Единая функция расчёта скидки `calcDiscount` используется apply/cart/createOrder — расхождения UI и чекаута исключены по построению.

## User Stories

1. Как покупатель, я хочу открыть `/cart` и увидеть список товаров из корзины со степперами и удалением, чтобы скорректировать состав до оформления.
2. Как покупатель, я хочу, чтобы количество менялось мгновенно (optimistic), а тоталы обновлялись, не дожидаясь ответа сервера.
3. Как покупатель, я хочу видеть блок доступных акций сверху корзины с кнопкой «Применить», чтобы узнавать об акциях до ввода кода; если условие акции сейчас не выполняется — кнопка disabled с причиной.
4. Как покупатель, я хочу видеть активную акцию ниже блока с суммой скидки и ✕, чтобы снять её в один клик.
5. Как покупатель, я хочу ввести промокод вручную (поле с предзаполнением из `?promo=`), чтобы применить код, которого нет в списке.
6. Как покупатель, я хочу, чтобы акции не складывались: применение другой заменяет активную.
7. Как покупатель, я хочу выбрать «Доставка / Самовывоз» на /cart, чтобы тоталы и подсказка о бесплатной доставке были честными; выбор доезжает в чекаут через `?fulfillment=`.
8. Как покупатель, я хочу строку «Добавьте товаров на X ₽ до бесплатной доставки», чтобы понимать порог.
9. Как покупатель, я хочу перейти к оформлению и увидеть товары замороженными (без степперов), поля контактов/адреса/комментария и финальные тоталы, чтобы подтвердить заказ одним экраном.
10. Как гость, я хочу оформить заказ без регистрации: имя + телефон + (адрес для доставки) + комментарий; заказать → квитанция с кнопкой «Скопировать ссылку отслеживания».
11. Как покупатель, я хочу, чтобы если промокод протух к моменту оформления, заказ НЕ создавался, скидка снималась с корзины и показывалась модалка с причиной, чтобы повторное «Оформить» прошло без скидки.
12. Как покупатель со скринридером, я хочу aria-live на тоталах, aria-ошибки на полях и фокус-ловушку модалок (WCAG 2.1 AA).
13. Как посетитель, я хочу бейдж Σqty в шапке (скрыт при 0), ведущий в /cart, чтобы видеть наполняемость корзины с любой страницы.
14. Как покупатель, я хочу, чтобы корзина переживала перезагрузку (httpOnly-cookie + БД) — проверка логина и слияния корзин переносится в этап 3.
15. Как разработчик, я хочу миграцию: `promotions.categoryId` (nullable FK restrict) + `minTotal`, `orders.deliveryFee`, таблицу `settings` — чтобы этап 5 построил формы без второй миграции.
16. Как разработчик, я хочу `getDeliverySettings()` (чтение `settings`, fallback на константы) — чтобы этап 5 заменил источник значений одной функцией.
17. Как разработчик, я хочу, чтобы `createOrder` сам считал скидку и доставку (клиент не присылает цены) — как и весь состав заказа, из БД.

## Implementation Decisions

- **Схема (одна миграция drizzle-kit, SQL в git)**: `promotions.categoryId: integer, nullable, FK → categories, onDelete: 'restrict'` (null = весь заказ; restrict — иначе удаление категории молча расширит скидку на всё); `promotions.minTotal: integer NOT NULL DEFAULT 0` (копейки, 0 = без условия); `orders.deliveryFee: integer NOT NULL DEFAULT 0` (копейки); таблица `settings (key text PK, value text NOT NULL)` — ключи `delivery_fee`, `free_delivery_threshold`.
- **Расчёт скидки — `calcDiscount(lines, promo)` в `lib/promo.ts`**, единая для applyPromoCode / страницы корзины / createOrder: база = вся корзина (`categoryId = null`) или Σ(`цена × qty`) только строк категории; percent → `floor(база × value / 100)`, fixed → `min(value, база)` (скидка не уводит базу в минус); условие `minTotal` сравнивается с **полной суммой товаров корзины** (не с суммой скоупа, без доставки); функция возвращает сумму и причины неприменимости (minTotal не выполнен / нет товаров скоупа).
- **Доставка**: `DELIVERY_FEE = 19900` (199 ₽), `FREE_DELIVERY_THRESHOLD = 100000` (1000 ₽) в `lib/constants.ts`; `getDeliverySettings()` читает `settings`, при отсутствии строк — fallback на константы; порог считается **от суммы товаров до скидки**; самовывоз — всегда 0 (строка «Доставка: —»); расчёт только на сервере в `createOrder` (клиент не присылает).
- **Actions**: `applyPromoCode` отклоняет с причиной («Нужен заказ от X ₽», «В корзине нет товаров из акции»); новый `removePromoCode` (сброс `promoId` корзины); `createOrder` — скидка через `calcDiscount`, `deliveryFee` из settings, итог = товары − скидка + доставка; **промо невалидно к моменту оформления → заказ не создаётся, promoId снимается с корзины, ActionResult error с причиной**; любые серверные ошибки createOrder открывают Dialog-модалку в чекауте; клиентская валидация полей (имя ≥ 2, телефон ≥ 10 цифр, адрес ≥ 5 для delivery) — inline с aria до отправки.
- **Поток страниц**: `/cart` — степперы (`useOptimistic` + setQty, min 1 / max 99, удаление ×), двухколоночная раскладка (desktop: sticky-тоталы справа; mobile: одна колонка); Tabs «Доставка / Самовывоз» — **локальное состояние страницы** (в БД не пишется), влияет на тоталы/подсказку; кнопка «Перейти к оформлению» → `/checkout?fulfillment=delivery|pickup` (disabled при пустой корзине); пустая корзина → карточка «Корзина пуста» + «В меню». `/checkout` — товары read-only (список из БД, без степперов), Tabs предзаполнены из `?fulfillment=` (можно поменять — payload решает), имя/телефон prefilled из сессии (гость — пустые), адрес — одно textarea «Улица, дом, квартира» (только для delivery), комментарий — textarea; пустая корзина при прямом заходе → `redirect('/cart')`; успех → `router.push('/orders/' + orderId)`.
- **Квитанция `/orders/[id]`**: номер (короткий uuid), бейдж статуса «Создан», состав order_items (снапшот), скидка (промо-имя), доставка, итог; кнопка «Скопировать ссылку отслеживания» (clipboard) + пояснение; доступ по неугадываемому uuid (этап 4 не изменит гард); не-uuid → `not-found` (как у товара, 51144e9).
- **Бейдж корзины**: layout передаёт в клиентский Header слот `<Suspense><CartBadge/></Suspense>`; CartBadge — асинхронный серверный компонент: сессия → корзина по userId, иначе cookie `cart_id`, иначе 0; показывает **Σqty** (суммарное количество), скрыт при 0; чтение динамическое (без тегов) — server actions сами пере-рендерят текущий маршрут, при навигации динамические скоупы всегда свежие.
- **Чтение корзины страницами**: новый helper `getCartForRead()` в `lib/cart.ts` — сессия → корзина по userId, cookie → корзина, иначе null; **не создаёт** корзину и не пишет cookie (создание — только в actions).
- **Сидер — заглушки до этапа 5** (акции будут создаваться из админки): «Счастливые часы» удалены; `SHAWARMA20` −20% → categoryId шаурма; `PIZZA300` −300 ₽ (minTotal = 100000) → categoryId пицца; `COMBO150` −150 ₽ → categoryId сеты; сидер обновляет акции по code — расширение схемы идемпотентно.
- **A11y (§7 чек-лист)**: тоталы в `aria-live="polite"`; степперы — кнопки с aria-label («Убрать одну», «Добавить одну»); ошибки полей — `aria-invalid` + `aria-describedby`; модалки — radix Dialog (фокус-ловушка); статус/скидка — не только цветом; только CSS-токены; контраст в обеих темах.
- **Кеш-политика**: корзина/чекаут/квитанция — динамические (cookies, без `'use cache'`); теги не добавляются; `updateTag('orders')` в createOrder остаётся; акции для промо-блока — существующий `getActivePromotions` (тег `promos`, окно на чтении).

## Testing Decisions

- Тестовый фреймворк отсутствует (vitest/Playwright — §9). Шов — запущенное приложение целиком; проверка внешнего поведения (разметка, HTTP, записи в БД), не внутренностей.
- Приёмочный сценарий (web-gui-tester): главная → 2×«Классическая» (680 ₽) + «Пепперони» (690 ₽) → /cart → SHAWARMA20 из блока → скидка −136 ₽ **только от шаурмы** (база 680 ₽), Пепперони без скидки → доставка бесплатная (сумма 1370 ₽ ≥ 1000 ₽) → «Перейти к оформлению» → /checkout (товары заморожены, итог 1234 ₽) → «Оформить» → квитанция /orders/[id]: состав-снапшот, скидка −136 ₽, доставка 0, итог 1234 ₽, кнопка копирования ссылки. Перезагрузка /cart — состав на месте. Пустая корзина: /cart → «Корзина пуста», /checkout → redirect.
- Негативные: неактивный/несуществующий код — отклонение; PIZZA300 при сумме < 1000 ₽ — кнопка disabled с причиной «Нужен заказ от 1000 ₽»; промо на категорию без её товаров — «В корзине нет товаров из акции»; `?product=<кривой uuid>`-аналог для /orders/[кривой uuid] → not-found.
- Инструменты: pnpm lint/tsc/build, docker build + prod compose, curl, web-gui-tester.

## Out of Scope

- Слияние гостевой корзины при логине и страницы входа/регистрации — этап 3 (критерий «корзина переживает логин» переносится туда); `/login` и `/promo` остаются 404 (этапы 2/3) — ссылки в шапке не трогаем.
- Трекинг с таймлайном и polling — этап 4 (квитанция — не трекинг).
- CRUD акций и форма «Настройки доставки» (settings) в админке — **этап 5** (внести в §6 AGENTS.md при завершении этапа: форма с полями имя/код/скидка/скоуп/minTotal/окно + настройки доставки); сидер — временный источник демо-акций.
- Мок-оплата (этап 9): чекаут без выбора способа оплаты, `paymentStatus` остаётся pending.
- Пуши/SMS «заказ готов» (этап 10), модификаторы, слоты доставки, несколько акций одновременно (§9).
