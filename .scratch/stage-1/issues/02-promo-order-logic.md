# 02: Единый расчёт скидки + доработка actions (промо, доставка)

**What to build:** Одна функция `calcDiscount` — единственный источник правды о скидке для apply, страницы корзины и createOrder. Actions доработаны: отклонение промо с причиной, снятие промо, серверный расчёт доставки, отказ оформления при протухшем промо (с удалением promoId).

**Blocked by:** 01

**Status:** resolved

- [x] `lib/promo.ts`: `calcDiscount(lines, promo)` → `{ amount, reason }` (или эквивалент): база = вся корзина (`categoryId = null`) или Σ(цена × qty) строк только этой категории; percent → `floor(база × value / 100)`, fixed → `min(value, база)`; `minTotal` сравнивается с полной суммой товаров корзины (без доставки); причины неприменимости: «Нужен заказ от X ₽», «В корзине нет товаров из акции» (база = 0)
- [x] `applyPromoCode`: валидация (isActive, окно) + проверка применимости через `calcDiscount` на текущей корзине — отклонение с причиной ошибки; перезапись `promoId` при применении другой акции (акции не складываются)
- [x] Новый `removePromoCode()`: сброс `promoId` корзины (для ✕ у активной акции)
- [x] `createOrder`: скидка через `calcDiscount` (на составе из БД); `deliveryFee` — сервер по fulfillment + settings (delivery ≥ порога → 0, иначе 19900; pickup → 0; клиент не присылает); итог заказа = товары − скидка + доставка
- [x] `createOrder`: промо на корзине невалидно (неактивно/вне окна/условие не выполнено) → **заказ не создаётся**, promoId снимается с корзины, ActionResult error с причиной (модалку покажет чекаут — тикет 05)
- [x] Клиентская валидация полей остаётся на чекауте; серверная — как есть (имя ≥ 2, телефон ≥ 10 цифр, адрес ≥ 5 для delivery)
- [x] `updateTag('orders')` при успехе; `revalidatePath('/')` — как было; корзина после неуспеха (снятие промо) тоже перевалидирована
