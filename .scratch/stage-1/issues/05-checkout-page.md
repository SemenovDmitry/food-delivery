# 05: Страница /checkout — подтверждение заказа

**What to build:** Финальный экран: замороженный состав, контакты/адрес/комментарий с inline-валидацией, финальные тоталы, оформление через createOrder; серверные ошибки — Dialog-модалка (включая протухший промо: промо снят, корзина обновлена, заказ не создан).

**Blocked by:** 02, 03

**Status:** resolved

- [x] `(shop)/checkout/page.tsx` + CheckoutForm: состав корзины read-only (из БД через `getCartForRead`, без степперов и удаления), активное промо и суммы — как на /cart
- [x] Пустая корзина при прямом заходе → `redirect('/cart')`
- [x] Tabs «Доставка / Самовывоз» предзаполнены из `?fulfillment=` (searchParams; по умолчанию delivery), можно поменять — финальный выбор уходит в payload
- [x] Поля: имя (prefill из сессии), телефон (prefill из сессии, без маски), адрес — одно textarea «Улица, дом, квартира» (только при delivery), комментарий — textarea; клиентская валидация до отправки (имя ≥ 2, телефон ≥ 10 цифр, адрес ≥ 5) — inline с `aria-invalid` + `aria-describedby`
- [x] Финальные тоталы: Товары / Скидка (с именем промо) / Доставка / Итого — считаются на сервере страницы (fulfillment из Tabs состояния — клиент пересчитывает по известным правилам, финальный расчёт за createOrder)
- [x] Кнопка «Оформить заказ» → `createOrder(payload)` → успех: `router.push('/orders/' + orderId)` (корзина очищена в транзакции)
- [x] Серверные ошибки → radix Dialog-модалка с текстом причины; для промо-ошибки корзина под модалкой обновляется (промо снят) — повторное «Оформить» проходит без скидки; модалка закрывается в «понять и закрыть»
- [x] A11y §7: фокус-ловушка Dialog, возврат фокуса на форму после закрытия, label + aria-invalid + aria-describedby
