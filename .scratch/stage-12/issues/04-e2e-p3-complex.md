# 04: e2e P3 — сложные интеграции (онлайн-оплата, регистрация+email через Mailpit, чат WS)

**What to build:** `e2e/p3-complex.spec.ts` (Q10). Сценарии: (1) **онлайн-оплата loopback** — чекаут гостя с radio «Онлайн-оплата» (Сбер активен из сидера) → redirect на pay-страницу `(provider)/orders/[id]/pay` (без шапки магазина) → отсчёт окна 5:00 → «Сбер» → заглушка банка → «Оплатить» → loopback-webhook (HMAC, серверная подпись) → трекинг: платёжный чип «Оплачено» **≤ 35 с** (поллинг доезжает); негатив внутри сценария не нужен (curl-негативы этапа 9 не переиспользуем — юнит-уровень HMAC покрыт тикетом 01). (2) **регистрация + привязка email** — рандомный телефон `+7 900 …` → /register визард (телефон → OTP 1111 → редирект /orders) → привязка email: форма на /email (или баннер /orders) → код **берём из Mailpit API** `GET http://localhost:8025/api/v1/messages` (парсить письмо, код — случайный, не 1111) → ввод → `emailVerified` (баннер исчез) → перелогин не нужен. (3) **чат гость↔оператор через реальный шлюз** (Q11) — guestContext: виджет поддержки на главной → открыть → написать сообщение (WS через :3001, NEXT_PUBLIC_WS_URL пекётся на тестовой сборке); adminContext: /admin/chats → таб «unknown» с бейджем появился → открыть таб → ответить; guestContext: ответ пришёл живьём ≤ 5 с (без перезагрузки, WS-фанаут). Нестабильность (фон-вкладки IAB-квирки не релевантны в headless chromium, но WS-рассинхрон возможен): допустим `test.fixme` с комментарием причины — не тащит весь сьют (решение гриллинга). Тест-данные: заказ/регистрация/тред — свои на ран (рандомный телефон — уже уникален).
